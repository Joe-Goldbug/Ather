# Eva：IA 与 Web3 首个 Demo 讨论总纲

整理日期：2026-10-05  
项目名称：**Eva**（本目录内 Web3 项目的唯一工作名称）  
文档用途：汇总 Eva 的项目陈述、IA 目标及 Web3 首版探讨，作为后续产品判断的工作底稿。本文是研究与产品建议，不代表新路线已经实现、上线或获得进一步开发授权。

## 先读结论

**Eva 的终极目标是做人类的 IA——增强人类智能。**产品应帮助人更好地理解、学习、推理、判断、创造与行动，并保留人的主体性。Self OS、自我模型、记忆、Agent 和区块链都是候选手段，不能替代这个目标。

## Eva 项目陈述（工作版）

**Eva 是一个以 AI 互动体验帮助人增强智能的项目。**用户带着情境或真实问题进入 Eva，先表达自己的判断；Eva 帮助用户检查证据、假设、盲点和可改变结论的条件；用户自己形成下一步行动，并在结果出现后复盘。Eva 要增强的是人的理解、推理、判断、创造与行动能力，让人更能掌握自己的选择。

首个轻量版本用一个清楚、可完成的思考闭环验证这个目标。Web3 为用户提供可选的个人思考记录版本核验；它只证明用户持有的记录与所提交版本相符，不为心理结论背书。RWA 收益抵扣使用成本是后续待验证的经济机制，不决定 Eva 是什么产品，也不承诺保本或免费使用。

从这个目标倒推，首个轻量 Web3 Demo 建议为：

> **用户面对一项真实或模拟的复杂问题，先独立判断；Eva 帮助其检查事实、假设、反例与不确定条件；用户重新判断并采取行动；之后回看真实结果。用户可以把自己确认的前后思考记录加密保存，并选择将记录版本的承诺登记到链上，以便独立核对记录在登记后是否被改动。**

Demo 的 Web3 核心是用户确认的认知过程记录版本，而不是人格 NFT、能力证书、收入代币或钱包连接本身。链上只核验特定文件与已登记承诺是否匹配，不能证明记录属实、决定正确、能力已经提高或心理测量有效。

**RWA 收益抵扣 Eva 的使用成本是一个候选费用模型，不是首版认知功能。**按当前讨论中的数字假设，200–500 美元本金不能覆盖每月 15–30 美元服务费；真实 RWA 也不等于保本、随时兑付或人人可持有。

目前没有确认首个 Demo 的正式名称、具体情境题、链、代币、RWA 合作方或上线计划。本文件给出推荐方案和验证门槛。

## 2. Eva 的终极目标与首版原则

### 终极目标

> **Eva 的终极目标是做人类的 IA——增强人类智能。Self OS 只是表现形式之一。**

此前的 IA 愿景口径将理解、学习、推理、判断、创造与行动列为可用于验证 IA 的维度，并要求人能理解依据、纠正系统和保留最终选择权。Eva 沿用用户在本轮确认的 IA 目标。画像更丰富、调用更多 Agent 或完成上链，本身不足以证明智能增强。

### 首版原则

1. **先指定要增强的人的能力。**本 Demo 推荐聚焦“面对复杂或不确定问题时，形成有依据、可修正的判断”。
2. **以任务表现代替人格标签。**记录用户在具体问题中的思路、假设、证据、纠正和行动；不把一轮表现泛化成永久人格结论。
3. **让人经过思考，而不是只接收答案。**Eva 要使用户看到事实、假设、反例与变化条件，并由用户作最终判断。
4. **先把 Web2 认知闭环做好。**AI 引导、私密记录、反馈与现实复盘直接承载 IA。
5. **Web3 只承担用户能实际使用的验证功能。**不因为参赛、钱包或技术栈而强行链上化。
6. **把可验证与真实分开。**链可以证明某个密文档版本与其承诺相符，不能证明文件内容真实或判断可靠。
7. **不把保存等同于模型使用许可。**每次调用 AI 的用途与数据范围应得到清晰控制；撤回访问无法召回第三方已收到或复制的内容。

## 3. 推荐的首个 IA × Web3 Demo

### 一句话

**Eva 帮用户经历一次“独立判断 → AI 帮助检查思路 → 用户修正 → 行动 → 结果复盘”的认知增强过程，并允许用户自行封存可核验的记录版本。**

### 用户流程（约 10–15 分钟，时间为原型目标）

| 步骤 | 用户动作 | Eva 功能 | 用户直接得到什么 |
|---|---|---|---|
| 1. 选一个问题 | 选短情境剧本，或输入自己的问题 | 说明目标、限制、已知信息与冲突；虚构内容标注清楚 | 将模糊纠结变成可以处理的问题 |
| 2. 写下起点 | 写初步选择、理由、信心及最大未知 | 保存用户确认的初始判断 | 留下结果发生前真正持有的判断 |
| 3. 检查思路 | 回应 AI 对证据和假设的追问 | 区分事实与推测；指出遗漏；提出反例和可能改变结论的条件 | 看到盲点和下一步需要查明的事情 |
| 4. 自己重新判断 | 保持或修改选择，说明依据 | 并排展示前后判断及修订理由；不代替用户定论 | 知道自己为何改变或为何坚持 |
| 5. 独立尝试 / 行动 | 在另一短情境独立使用方法，或设一个现实可观察的小行动 | 保存行动、条件与复盘时间 | 把思考迁移到新问题或现实行为 |
| 6. 结果复盘 | 结果出现后记录发生了什么 | 将结果与先前依据和不确定条件相比较 | 从结果修正下一次判断 |
| 7. 可选链上封存 | 决定是否封存自己的记录 | 由用户钱包对本地加密档的承诺签名/登记，并提供独立核验 | 自己保存并核验这份记录的版本历史 |

### Demo 内容示例

主题可以设计成“信息相互矛盾时，你会如何判断下一步”：

- 情境给出一个有时间压力的主张与不完整证据；
- 用户先写判断和信心，不看 AI 结论；
- Eva 追问：“哪些是已知事实？哪条是推测？什么新信息会让你改变想法？”
- 用户检查证据、补充限制，再次表达判断；
- 新情境检验用户能否独立使用这套步骤；
- 如果用户愿意，可把判断、来源、修订、行动和结果导出、加密并封存版本。

场景只用于观察本次推理过程，不给用户贴“抗压型”“系统性思考 High”等固定标签。具体题目应经产品设计和事实检查，不在本文件中视为已定。

### 链上承诺的技术与语义边界

链上只应登记随机化/加盐的文件承诺、必要版本关系与登记时间，不登记原文、聊天内容、人格/情绪标签、评分或原始心理指标。用户下载原文、盐值与验证材料，独立页面能检查文件是否与承诺匹配。

这可以支持“用户手中的记录与某个已登记版本一致”及“该承诺在某个链上时间后不能由单方静默替换”。它**不能**支持以下结论：

- 用户所写事实已经被独立证实；
- Eva 的分析没有错误；
- 用户已经达到某种能力等级；
- 用户智商或认知能力提高了；
- 用户一定拥有对应法律权利；
- 哈希可以恢复已丢失文件，或撤销链上永久公开的信息。

公开链上的钱包地址、时间和交互模式也可能被关联。只发布哈希并不自动实现匿名；低熵分数或常见人格标签的普通哈希也可能被枚举。Demo 必须使用随机盐/高熵随机数，明确告知链上持久性，并默认不封存。

## 4. Web2 与 Web3 的分工

| 能力 | 首版归属 | 理由 |
|---|---|---|
| 剧本、问题输入、对话、界面 | Web2 | 交互需要可迭代，属于认知体验 |
| 事实/假设区分、反例提示、推理引导 | Web2 | 这是 IA 功能本身，区块链不会提高推理质量 |
| 初始判断、用户修订、反馈及现实结果 | Web2 私有数据 | 需要用户访问控制、修改、导出、删除和备份 |
| 用途授权与撤回 | 首版 Web2 权限/API | 链上授权本身不保证读取服务会执行拒绝；撤回也不能召回已复制内容 |
| 完整思考记录的下载与恢复 | Web2 / 用户控制存储 | 链上哈希不能恢复原文 |
| 用户主动确认的记录版本承诺 | Web3 可选 | 可由独立核验工具比对，减少单纯依赖 Eva 单方数据库 |
| 链上证明/签名声明 | Web3 可选 | 只证明签署者/记录和版本，不证明声明真实或科学有效 |
| RWA 收益用于抵扣体验成本 | 后续候选 | 必须先有可用的合法产品、适格用户、可兑现收益、实际服务成本与清晰结算 |
| 公开心理分数、情绪、人格和聊天内容 | 不上公开链 | 对 IA 没有必要的链上好处，且形成隐私与关联风险 |

**链不是可验证信息的唯一路径。**W3C 可验证凭证标准允许使用可信数据库或分布式账本作为数据登记簿；核验凭证不代表声明内容为真。EAS 同时支持链上和链下证明。故首版 Web3 的理由应是用户需要独立核验公共时间戳/版本承诺，而不是“证明只能上链”。

### 首版链选择状态

此前讨论过 Solana、Ethereum、Base、Arbitrum、Robinhood Chain、Hyperliquid 和 Tempo，问题背景包括深圳 Solana 活动、认知记录证明以及未来可能的 RWA。**当前没有选定 Eva 主链，也没有批准代币或 RWA 部署。**

第一 Demo 的功能应该先定，再根据证明服务、钱包体验、费用、目标用户和实际部署支持选择网络。如果做 EAS/SAS 时间戳锚定原型，可以先选一条支持该服务且最适合参赛/测试的链；这只决定一个 Demo 的实现，不等于 Eva 永久主链决策。EVM 技术栈与现有 TypeScript 一致，本身不能证明 Base/Arbitrum 比 Solana 对用户更有用。

## 5. 对 Compute Vault / RWA 算力基金方案的核算

### 用户设想

用户持有生息资产，实际收益抵扣 Eva 的 AI 使用成本，让资产为持续认知支持出资；用户掌握本金、可退出。

### 账目核算

贴文使用 5% 年收益和每月 15–30 美元费用作为示例。按简单年化估算，不计复利、价格变化、产品费、链费、税费和损失：

| 投入本金 | 5% 假设的年收益 | 月均收益 | 说明 |
|---:|---:|---:|---|
| 200 美元 | 10 美元 | 约 0.83 美元 | 不能覆盖每月 15–30 美元 |
| 500 美元 | 25 美元 | 约 2.08 美元 | 不能覆盖每月 15–30 美元 |
| 3,600 美元 | 180 美元 | 约 15 美元 | 只在 5% 持续且无其他成本时，理论覆盖 15 美元/月 |
| 7,200 美元 | 360 美元 | 约 30 美元 | 只在 5% 持续且无其他成本时，理论覆盖 30 美元/月 |

因此，“存 200–500 美元即可终身免费享受高级 AI”在数字上不成立。15–30 美元是原文里的假设，不是本次已经核实的 Eva 定价或单用户月成本。

Ondo 的 USDY 官方资料将其描述为有资格和地域限制的代币化票据/收益产品，不是所有人都可直接参与的银行存款或美国国债所有权。产品收益率会调整，官方风险说明包含本金损失，最高可损失全部购买金额。因此不能向用户保证本金安全、收益固定、随时收到法币赎回或终身免费。

### 合理的后续表述

若未来证据支持，可验证较窄机制：

> 用户在符合资格且了解风险的前提下持有外部收益产品；已实现的净收益可按公开规则抵扣一定的 Eva 使用额度，抵扣数随实际收益及 Eva 边际服务成本变化。

开展真实资产接入前，至少要量得每次 IA 体验的模型/存储等真实成本，定义净收益、兑换、费用、收益不足、资产价格下跌、暂停服务与提现等待的处理，并核实发行方条款、用户适格、所在司法辖区及分发权限。不能将上述建议理解为已获法律批准的产品。

首 Demo 可展示清楚标注的费用模型模拟，不收用户资金、不部署自有 RWA Vault、不宣传收益或保本。Eva 首版的认知能力必须由体验本身证明，不能让用户购买 RWA 才能体验目标功能。

## 7. 讨论过但不作为当前首版决定的方向

| 方向 | 当前判断 | 主要原因 |
|---|---|---|
| 人格、情绪或记忆数据本身 NFT/RWA 化 | 不进入首版 | 与 Eva 的人的智能增强目标不符；隐私、权利和真实买方都未解决 |
| 向用户发自己的 Token / ICO 奖励 | 不进入首版 | 不能自动带来真实价值或持续激励，且会引入发行、治理、流动性和监管复杂度 |
| “Agent 收入流 Token”或把未来收入打包出售 | 不进入首版 | 没有已验证收入流、客户、贡献分配和合同权利；改代币名称不解决这些问题 |
| 外部 Agent 市场、数据买家市场 | 当前不做 | 会把首版推向中介/撮合路线，且用户明确要求暂不考虑 |
| 学校、教师审核、能力招聘、Talent Protocol 类验证 | 当前不做 | 用户明确排除学校与中介；AI coding 现实也不再以教师审核作为产品前提 |
| 把用户链接钱包并付固定 Token 当产品 | 不成立 | 没有说明人获得何种 IA 能力或实际结果 |
| 只做钱包连接、EAS/SAS 记录页或 SBT | 不成立 | 链上工具不能代替 Eva 的核心认知体验 |
| 用人格标签或一次游戏结果生成“抗压/推理能力权威证书” | 不进入首版 | 单次结果不足以证明稳定特质或客观能力等级 |
| 链上算力资金池 / USDY RWA Vault | 不进入首 Demo 的真实资金范围 | 收益小于先前方案声称的服务成本；资格、收益波动、损失和兑付依赖未闭环 |
| 将“游戏改变世界 beta1”与 Eva 直接合并 | 暂不合并 | 当前对话没有确认它是 Eva 的子产品；需保持项目边界，避免把社会模拟/GameFi 任务混入 Eva IA 主目标 |

上述“不进入首版”表示当前产品设计判断，不等于宣告这些技术或概念绝对不可用。

## 9. 从 Eva IA 到未来 Web3/RWA 的阶段条件

这是方向图，不是既定排期。每一步都必须由用户价值和真实权利/支付证据触发。

| 阶段 | Eva 帮人什么 | 需要积累的功能/条件 | 此时链上可能做什么 |
|---|---|---|---|
| **第一步：个人 IA** | 帮一个人理解复杂问题、检查推理、修正判断并行动 | 真实任务闭环、用户纠正、来源边界、隐私和可导出记录；证明体验让用户受益 | 可选地封存用户确认的记录版本，提供可独立核验的时间锚点；不产生人格资产或 RWA |
| **第二步：持续个人增强** | 基于用户认可、不断修正的经验，在不同问题中提供更合适的思考支持 | 可靠的长期经验更新机制；资料按用途授权；用户可检查、改正、导出、删除 | 用户对版本/来源的便携证明；能真实抵御单方篡改的状态才值得上链 |
| **第三步：人和 Agent 协作** | 用户可在自身判断控制下使用 Agent 完成部分任务 | Agent 权限、明确职责、来源归因、用户审阅；若涉及多人贡献，还须有贡献确认、责任与收益合同 | 真实跨 Agent/跨平台核验需求出现后再考虑授权状态、支付和分账；没有参与方就不建中介市场 |
| **第四步：成果权利与 RWA** | 用户的研究、代码、设计、方法或其他成果在明确许可后被使用，创作者可掌握约定权利 | 可识别作品/权利主体；明确授权范围、期限、区域、用途；真实需求方、交付验收、合同义务和收入流；违约/争议处理 | 对实际存在且可执行的许可费、应收款或合同分成进行登记/结算。只有法律文件和现金流支持时才评估代币化 |

这些名词不能互相替代：知识产权许可是合同权利；交付后尚未收款的应付金额可能形成应收款；按合同持续取得的许可费可能形成收入权；按照实际销售分成需要定义可审计收入与扣除项。某项内容被写入链或铸成 NFT，不会自动创造其中任何权利。

## 10. 验证计划与停止条件

### 先验证 Eva 是否增强了人的思考

至少邀请真实目标用户完成同类任务的基线和 Eva 辅助版本。设计时保存每个任务的：

- 用户初始判断与信心；
- 用户识别的事实/假设及其证据来源；
- 是否发现可能推翻判断的关键条件；
- 用户最终判断的理由变化；
- 在一个新情境中的独立尝试；
- 现实下一步与之后的结果复盘。

主要看用户是否更能说明依据、识别不确定性、修正无据假设，并采取自己认可的下一步。不能让同一个 AI 独自给自己打分后宣称 IA 提升；评分规则、任务等值性和评估者一致性需在测试方案中说明。一次 Demo 不能证明 IQ 提升或稳定能力增长。

### 再验证 Web3 是否给用户带来增量

- 用户能否下载并恢复原始记录；
- 独立核验页面能否检查持有文件与链上承诺是否一致；
- 文件被改动后，核验能否失败；
- 钱包签名、链费、隐私说明是否造成过高进入负担；
- 目标用户是否理解并主动需要这份外部可核验版本，而非只因 Demo 展示而点击；
- 链上持久性和钱包关联风险是否被理解。

如果用户实际并不需要独立版本核验、独立导出已能满足需求，或签链带来的隐私/使用负担大于验证利益，则把 Web3 保持为可选扩展，不强制成为 IA 的入口。

### 再验证算力抵扣

- 量清完整体验的真实边际成本与周期模型成本；
- 确认可访问的资产产品、地区/投资者资格、真实净收益、提现和法律安排；
- 与普通订阅/免费额度比较用户总成本与收益；
- 只以已实现并可结算的金额发放抵扣额度；
- 明示资产风险，明确没有保本承诺；
- 若不足以明显降低用户实际付费，停止投入资金 Vault 研发。

## 11. 首版建议范围

### Demo 核心

1. 一个短情境或用户自己的实际问题。
2. 用户的初始判断、理由和不确定性。

5. 第二个独立尝试或一个可复盘的小行动。

- 强制钱包开户；
- 学校、教师审核、人才撮合或外部中介；
- 未经验证的跨用户排名、可交易信誉和“权威能力证书”。

## 12. 术语表

- **IA（Intelligence Amplification）**：增强人的智能；本文落实为对理解、学习、推理、判断、创造、行动的实际支持。
- **记录版本承诺**：对特定文件计算出的密码学摘要/承诺；能检查文件是否匹配登记版本，不证明内容为真。
- **Attestation（证明声明）**：某个签发者对结构化声明签名/登记；是否相信内容取决于签发者、证据和验证规则。
- **RWA**：与现实资产、合同或现金流相关联的链上表示；上链本身不创造底层产权、兑付能力或收益。
- **Compute Vault**：把外部收益用于支付计算/模型使用额度的候选机制，必须以净收益、真实服务成本、准入和风险规则为依据。
- **“可携带/可自持”**：用户能导出、恢复并授权自己记录；链上登记不是备份，钱包也不自动保护隐私。
